## 0. 仕様の要点（§2.6）

- 背景: 補償は保険会社との別契約に切り出す方針。クライアントが保険業の免許を持たないため、アプリ上での販売は保険業法上のリスクがある
- 購入 UI（料金プラン画面の補償オプション）を非表示にする。**コードは削除せずフラグで制御**（将来の復活に備える）
- お問い合わせの「お問い合わせ内容」に「給与未払いについて」を追加（未払い発生前の相談窓口）
- トラブル報告のカテゴリに「給与未払い」を追加（発生後の当事者間トラブルの窓口）
- 規約・FAQ・特定商取引法ページの補償記載を修正
- 既存契約者: いない（未リリース）。契約者移行は不要

## 1. 調査結果と確認事項

| # | 項目 | 調査結果 / 提案 |
|---|---|---|
| Q1 | **非表示の切り替え方** | 環境変数 `NEXT_PUBLIC_COMPENSATION_OPTION_ENABLED`（`"true"` のときだけ表示。**未設定 = 非表示**）。staging / 本番は何も設定しなければ非表示になり、復活させたいときは変数を足すだけでコード変更不要。画面だけでなく Server Action（Stripe Checkout・銀行振込申込）も同じ判定で新規申込を拒否する（URL 直叩き対策） |
| Q2 | **加入中の人の扱い** | 本番に契約者はいないが、seed に補償加入中のテストユーザーが 2 人いる。非表示中でも「加入中の補償」だけは行を出し、**解約ボタンのみ**使える（新規・変更はできない）。復活時の解約導線も同じ場所なので追加コード最小 |
| Q3 | **お問い合わせ内容の追加位置** | 「給与未払いについて」を「その他」の直前に追加（登録方法 / 料金について / 仕事掲載 / 協力会社募集 / 職人募集 / **給与未払いについて** / その他） |
| Q4 | **トラブル報告カテゴリの追加位置** | 「給与未払い」を「支払いトラブル」の直後に追加（連絡が取れない / 支払いトラブル / **給与未払い** / 仕事内容が違う / 迷惑行為 / その他）。既存の「支払いトラブル」はそのまま残す（発注者側の支払い遅延など未払い以外も含むため） |
| Q5 | **法務ページ** | 規約・FAQ・特商法・プライバシー（`docs/legal/*.md` と画面）を全文確認したが、**補償オプションの記載は元から無い**（「保険」の語は労災保険の一般論のみ）。修正対象なし。FAQ に「給与未払いの相談窓口」の Q&A を新設するかは要判断（提案: 今回は追加しない。文言は法務確認が必要なため、必要なら別途） |
| Q6 | **管理画面** | ADM-008（ユーザー一覧）の補償加入者絞り込み、ADM-025/026 の銀行振込申込の表示・有効化はそのまま残す（運営用。テスト用の加入者を扱えるようにしておく） |
| Q7 | **メール・Webhook** | 補償の有効化・解約・支払失敗メールと Webhook 分岐は削除しない（Stripe 側の既存サブスクからのイベントに備える。コードは温存の方針どおり） |

## 2. 受け入れ条件（案）

### A. 補償オプションの非表示
1. 環境変数未設定の状態で料金プラン画面（CLI-026）を開くと、オプション欄に「補償（受注者向け）」の 2 行が表示されない（急募・動画系はそのまま）
2. 環境変数 `NEXT_PUBLIC_COMPENSATION_OPTION_ENABLED=true` を設定すると従来どおり表示・申込できる
3. 非表示中に Server Action を直接呼んでも、補償の Stripe Checkout と銀行振込申込は「現在お申し込みを受け付けていません」で拒否される
4. 補償に加入中のユーザーは非表示中でも自分の加入行（ご利用中 + 解約ボタン）が見え、解約できる。もう一方の補償への切り替え申込はできない
5. 基本プラン解約ダイアログの「※加入中の補償オプションは…」の注意書きは、加入中のときだけ出る（現状どおり）

### B. 給与未払い窓口
6. お問い合わせ（COM-008）の「お問い合わせ内容」に「給与未払いについて」が選べる。送信すると既存どおり保存・メール送信され、運営宛メールと管理画面にその種別が出る
7. トラブル報告（COM-012）の「トラブル種類」に「給与未払い」が選べる。送信・メール・管理画面は既存どおり
8. 保存形式はラベル文字列のまま（DB 変更なし）。管理画面の絞り込み（あれば）は定数から自動で増える

### C. 品質
9. vitest: 非表示時の Server Action 拒否 / 表示時の従来テスト（環境変数を立てて実行）/ 定数追加の Zod 検証。E2E: 非表示の確認（billing.spec の補償期待値を反転）、お問い合わせ・トラブル報告で新項目を選んで送信
10. steering（product / screen-map）・CLAUDE.md・`.env.local.example` の更新

### 意図的な除外
- 補償関連コード（Checkout / Webhook / メール / 管理画面）の削除
- FAQ への Q&A 新設（Q5）
- 補償の既存契約者の移行処理（対象なし）

## 3. 設計方針

### 3.1 フラグ
- `src/lib/billing/options.ts` に `isCompensationOptionEnabled()`（`process.env.NEXT_PUBLIC_COMPENSATION_OPTION_ENABLED === "true"`）を追加。クライアント / サーバー両方から同じ関数を使う
- `.env.local.example` に `NEXT_PUBLIC_COMPENSATION_OPTION_ENABLED=` を追記（コメントで「未設定 = 非表示」を明記）

### 3.2 コード
| 箇所 | 変更 |
|---|---|
| `billing/page.tsx` → `BillingClient.tsx` | 補償 2 行を `isCompensationOptionEnabled() \|\| 加入中` のときだけ描画。非表示中は加入中の行だけ「ご利用中 + 解約」を出し、申込・切替ボタンは出さない |
| `billing/actions.ts`（Stripe） / `bank-transfer-actions.ts`（銀行振込） | 補償の申込は `isCompensationOptionEnabled()` が false なら早期 return（`COMPENSATION_OPTION_DISABLED_MESSAGE`） |
