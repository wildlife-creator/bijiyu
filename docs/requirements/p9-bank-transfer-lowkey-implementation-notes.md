# P9「銀行振込の導線を控えめにする（案 A）」実装メモ（ユーザー承認済み）

作成: 2026-09-04。承認: 同日（Q3 の Q17 文言は末尾の一文「請求書をお送りし、ご入金の確認後にご利用開始となります。」を削除して確定。代理登録の運営宛通知は送らない。他は提案どおり）。背景: 銀行振込はリリース後の運営負荷（請求書発行・入金確認・期限管理）が大きいため、機能は残しつつ**積極的には出さない**方針（ユーザー相談 2026-09-04）。クライアントにはまず案 A の形を見せ、「やはりプラン内にボタンを置きたい」となれば設定 1 つで戻せるようにしておく。
親ドキュメント: `docs/requirements/spec-changes-202608.md` §2.1(1)（銀行振込フロー）。P2 の実装メモ・E2E を前提にする。
作業ブランチ（予定）: `p9-bank-transfer-lowkey`（`feature/spec-changes-202608` = P1〜P8 マージ済み `b9cc43c` から分岐）。

## 0. 案 A の要点

- 料金プラン画面（CLI-026）から「銀行振込で申し込む」ボタンを消し、「銀行振込をご希望の方はお問い合わせください」の案内だけ置く
- よくある質問に「お支払い方法」の項目を整え、クレジットカードと銀行振込が可能で、銀行振込は問い合わせ、と記載する
- お問い合わせ内容に銀行振込の相談項目を足し、運営が仕分けしやすくする
- 運営は問い合わせを受けたら、管理画面から**銀行振込の申込を代理登録**し、以降は既存の流れ（請求書送付済 → 入金確認して有効化 → 期限バッジ・期限通知）をそのまま使う
- ボタンの表示は環境変数で切り替え（補償オプションと同じ方式）。**未設定 = ボタン非表示**、`true` で従来どおり各プラン・各オプションにボタンが出る

| Q2 | **お問い合わせ内容の項目名と位置** | 「お支払い方法（銀行振込）について」を「料金について」の直後に追加 |
| Q3 | **よくある質問 Q17 の文言（案）** | 現行「A. Stripeを利用したクレジットカード決済（Visa/Mastercard/JCB/Amex）に対応しています。決済は即時に行われます。」→ **案**「A. Stripeを利用したクレジットカード決済（Visa/Mastercard/JCB/Amex）と、銀行振込に対応しています。クレジットカード決済は即時に行われます。銀行振込をご希望の場合は、お問い合わせ窓口までご連絡ください。」（確定） |

| Q6 | **本人の直接申込（URL 直叩き）** | ボタン非表示のときは本人からの申込処理も拒否する（「銀行振込をご希望の場合はお問い合わせください」）。運営の代理登録だけが入口になる |
| Q7 | **既存の申込・契約** | 影響なし。seed の申込受付中ユーザー・銀行振込契約中ユーザーはそのまま表示・操作できる |

## 2. 受け入れ条件（案）

### A. 料金プラン画面（CLI-026）
1. 環境変数 `NEXT_PUBLIC_BANK_TRANSFER_SELF_SERVICE_ENABLED` 未設定のとき、各プラン・各オプションの「銀行振込で申し込む」ボタンが出ない。代わりに Q1 の案内文（お問い合わせへのリンク付き）が出る
2. 環境変数を `true` にすると従来どおりボタンが出て申し込める（P2 の E2E がそのまま通る）
3. 申込受付中・銀行振込で契約中の表示は環境変数に関係なく従来どおり
4. ボタン非表示のとき、本人の申込処理（Server Action）を直接呼んでも拒否される（Q6）

### B. 運営の代理登録（ADM-025）
5. ADM-025 に「申込を登録する」があり、メールアドレスで会員を特定 → 対象と支払サイクルを選んで登録できる。金額（本体・初回事務手数料の有無）は本人申込と同じ計算になる
6. 登録した申込は一覧に「申込受付」で並び、ADM-026 で「請求書送付済」「入金確認して有効化」「取消」ができる（既存）。監査ログに運営操作として残る
7. 登録時に申込者へ控えメールが届く。運営宛通知は送らない
8. 本人申込と同じ二重申込チェック（同じ対象の処理中申込があれば拒否、Stripe 契約中のプラン申込は拒否）が効く
9. 対象会員が退会済み・担当者（staff）・admin の場合は登録できない

### C. 案内・窓口
10. お問い合わせ内容に「お支払い方法（銀行振込）について」が選べ、送信・メール・管理画面は既存どおり
11. よくある質問 Q17 と特定商取引法ページの文言が Q3 / Q4 のとおりになり、md と画面の一致検証が通る

### D. 品質
12. vitest: 本人申込のフラグ拒否 / 代理登録の Server Action（正常・退会済み・二重申込・staff）/ 法務本文一致。E2E: ボタン非表示と案内文、ADM-025 からの代理登録 → 請求書送付済 → 有効化 → 会員の /billing で「ご利用中」（P2 の通しを代理登録起点に組み替え）。本人申込の E2E は環境変数 `true` のときだけ実行
13. steering（product / screen-map）・CLAUDE.md・`.env.local.example` の更新

### 意図的な除外
- 銀行振込のコード削除（フラグで温存）
- 会員自身が「銀行振込を希望」とアプリ内で申告するボタン（お問い合わせで代替）
- 請求書 PDF の発行・振込先の表示（従来どおりアプリ外）
