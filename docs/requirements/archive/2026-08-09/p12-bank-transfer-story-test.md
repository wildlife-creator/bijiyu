# P12 銀行振込 ストーリー形式の目視テスト（開発環境）

作成: 2026-09-16。対象: `p12-bank-transfer-onoff` ブランチ（`docs/requirements/p12-bank-transfer-onoff-implementation-notes.md`）。
開発環境で、登場人物になりきって順に操作する。各ストーリーは「前」（操作前の状態）→「操作」→「後」（変わったこと）の順。

## 準備

- `supabase start` と `npm run dev` が起動していること
- **最初に `supabase db reset`**（登場人物の初期状態を作る。途中で失敗したらここからやり直す）
- アプリ: `http://127.0.0.1:3000` / 管理画面: `http://127.0.0.1:3000/admin/login` / 届いたメール: `http://127.0.0.1:54324`
- パスワードは全員 `testpass123`

| 登場人物 | ログイン | 初期状態 |
|---|---|---|
| 振込一郎（受注者） | `bank-transfer-e2e@test.local` | 無料プラン。これから銀行振込で契約したい |
| 振込次郎（受注者） | `bank-requested@test.local` | 先週「ライトプランを銀行振込で」とお問い合わせ済み（まだ有効化されていない） |
| 振込花子（発注者・振込商店） | `bank-client@test.local` | スタンダードプランを銀行振込で契約中 |
| 運営 | `admin@test.local` | 管理画面 |

## ストーリー 1：振込一郎が銀行振込で契約したい

### 1-1. 一郎がお問い合わせを送る

**前**: 一郎はまだ無料プラン。
1. 一郎でログイン → 料金プラン画面 `/billing` を開く
   - [ ] 基本プランの下に「銀行振込をご希望の方はお問い合わせください。」のリンクがある
   - [ ] 「銀行振込で申し込む」というボタンは**無い**
2. リンクからお問い合わせ `/contact` へ
   - [ ] 氏名「振込一郎」・メールアドレス・所在地「東京都」が**最初から入っている**（電話番号は空）
   - [ ] 「お問い合わせの種類」に「お支払い方法（銀行振込）について」がある
3. 種類で「お支払い方法（銀行振込）について」を選ぶ
   - [ ] 「希望プラン」の欄が出る（ライト／スタンダード／プレミアム／ハイエンド／動画 3 種）
   - [ ] 一度「料金について」に変えると希望プランの欄が消え、戻すとまた出る
4. 会社名「振込一郎建設」、電話番号、利用目的、業種、希望プラン「スタンダードプラン」、詳細を入れて送信
   - [ ] 「お問い合わせを受け付けました。」

**後**: メール受信箱（`:54324`）
   - [ ] 一郎宛「お問い合わせを受け付けました」
   - [ ] 運営宛「お問い合わせを受信しました」に**「希望プラン: スタンダードプラン」**の行がある

### 1-2. 運営が確認して有効にする（入金確認後の想定）

**前**: 一郎は無料プランのまま。
1. 運営でログイン → メニュー「銀行振込お問い合わせ一覧」
   - [ ] 見出しが「銀行振込お問い合わせ一覧」
   - [ ] 上に一郎（希望：スタンダードプラン）、下に次郎（希望：ライトプラン）が並ぶ。ステータスの印は無い
   - [ ] 一郎の行の「お問い合わせ詳細」を開くと「希望プラン」の行がある → もどる
2. 一郎の行の「ユーザー詳細」を押す
   - [ ] ユーザーアカウント詳細が開き、下のほうに「銀行振込」の枠がある
   - [ ] 枠には「基本プラン」の選択と「有効にする」、「動画プラン」の選択と「動画プランを有効にする」だけ（年払い・開始日・期限の入力は無い）
3. 基本プランで「スタンダードプラン」を選び「有効にする」→ 確認ダイアログの文面を読む → 「有効にする」
   - [ ] 「スタンダードプランを有効にしました」
   - [ ] 「発注者詳細を開く」のリンクが出る
   - [ ] 枠が「現在: スタンダードプラン（銀行振込）」「変更する」「無効にする」に変わる

**後**:
   - [ ] メール受信箱に一郎宛「プランのお申し込みを承りました」、運営宛「プランの新規お申し込みがありました」
   - [ ] 「発注者詳細を開く」→ 発注者詳細でも「プラン: スタンダード（銀行振込）」と同じ「銀行振込」枠が出る（月払い／年払い・期限の表示は無い）

### 1-3. 一郎の画面はどうなったか

1. 一郎でログインし直して `/billing`
   - [ ] スタンダードに「ご利用中」
   - [ ] 「お支払い方法: 銀行振込」「変更や解約は運営までご連絡ください」「カード払いへ切り替える場合は…」の案内
   - [ ] 「解約する」「お支払い情報を管理する」は**無い**
   - [ ] 現在のプランに「カード払いに切り替える」、他のプランに「カード払いで申し込む」が押せる（押すと Stripe のテスト決済画面へ。ここでは押さなくてよい）
2. マイページ
   - [ ] 発注者向けのメニュー（案件を掲載する等）が出ている

## ストーリー 2：振込花子（契約中）のプランを変える → やめる

### 2-1. 変更する（発注者詳細から）

**前**: 花子はスタンダードを銀行振込で契約中。
1. 運営 → 発注者アカウント一覧で「bank-client」を検索
   - [ ] 「振込商店」の行に「プラン: スタンダード（銀行振込）」。「期限間近」などの印は**無い**
2. 行を開く → 「銀行振込」枠
   - [ ] 「現在: スタンダードプラン（銀行振込）」
3. 「プレミアムプラン」を選び「変更する」→ 確認 → 「変更する」
   - [ ] 「プレミアムプランに変更しました」、枠が「現在: プレミアムプラン（銀行振込）」
   - [ ] 上部の「プラン: プレミアム（銀行振込）」も変わる

**後**: 花子でログイン → `/billing`
   - [ ] プレミアムに「ご利用中」、お支払い方法は銀行振込のまま

### 2-2. 無効にする（契約をやめる）

**前**: 花子はプレミアムを銀行振込で契約中。花子で `/mypage` に発注者向けメニューがあることを見ておく。
1. 運営 → 発注者詳細（振込商店）→ 「無効にする」→ 確認ダイアログの文面（案件終了・担当者停止・返金はアプリ外）を読む → 「無効にする」
   - [ ] 「無効にしました」
   - [ ] **自動でユーザーアカウント詳細に移る**（発注者ではなくなるため）。枠は「有効にする」の状態に戻っている

**後**:
   - [ ] メール受信箱に花子宛「有料プランのご解約が完了しました」
   - [ ] 花子で `/billing` → 無料プランに戻り、`/mypage` から発注者向けメニューが消えている
   - [ ] 運営で「発注者アカウント一覧」→ 振込商店は「退会済み」ではなく、プランが「—」（銀行振込の表示が消えている）

### 2-3. もう一度有効にする（再契約）

1. 運営 → ユーザーアカウント一覧で「bank-client」→ 詳細 → 「銀行振込」枠でライトプランを「有効にする」
   - [ ] 「ライトプランを有効にしました」。以前の表示名「振込商店」がそのまま使われる（発注者詳細で確認）

## ストーリー 3：動画プランを銀行振込で買う

**前**: 運営 → ユーザーアカウント一覧 → 絞り込み「プロフィール動画」→ 一郎は出ない。
1. 一郎のユーザー詳細 → 「銀行振込」枠の動画プランで「プロフィール動画制作プラン」を選び「動画プランを有効にする」→ 確認 → 「有効にする」
   - [ ] 「プロフィール動画制作プランを有効にしました」

**後**:
   - [ ] メール受信箱に一郎宛「動画オプションのお申し込みを承りました」、運営宛「動画オプションの新規お申し込みがありました」
   - [ ] ユーザーアカウント一覧の絞り込み「プロフィール動画」で一郎が出る
   - [ ] 一郎の `/billing` でプロフィール動画制作プランが「購入済み」
   - [ ] 発注者詳細（一郎）の「オプション加入状況」でプロフィール動画にチェック

## ストーリー 5：契約主体になれない人には枠が出ない

1. 運営 → ユーザーアカウント一覧で担当者アカウント（`staff@test.local`）を開く
   - [ ] 「銀行振込」枠が**無い**
2. 退会済みのユーザー（`frozen-admin@test.local` など一覧で「※退会済み」の人）を開く
   - [ ] 「銀行振込」枠が**無い**

## 開発環境ではできないこと（staging で確認）

- **カード払い → 銀行振込に切り替える**: 実際に Stripe の契約を止めるため、Stripe にテスト契約がある会員が必要。ローカルのカード払いテストユーザー（`client@test.local` 等）は Stripe 側に契約が無く、押すと「カード払いの停止に失敗しました」になる（正常な拒否）。staging では: 発注者詳細 → 「銀行振込」枠に「現在: 〇〇プラン（クレジットカード・期間終了日 …）」と「銀行振込に切り替える」が出る → 押すと Stripe 側の契約が canceled になり、枠が「現在: 〇〇プラン（銀行振込）」に変わる。案件・担当者はそのまま
- **銀行振込 → カード払い**: 「カード払いで申し込む」→ Stripe のテスト決済を完了 → Webhook が届くと、`/billing` が「お支払い方法: クレジットカード」に変わり、管理画面の枠も「現在: 〇〇プラン（クレジットカード…）」になる。銀行振込の契約は自動で終了（案件はそのまま）。ローカルでも `stripe listen` で Webhook を転送すれば確認できる

## 終わったら

- `supabase db reset` で初期状態に戻す（次回の E2E のため）
